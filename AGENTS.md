# Agent guidance — jovian/venusian-pluto

1. **What it is:** the `plutovg` rasterization and painting drivers for Venusian Topside, on ext-plutovg. `PlutoVGRasterizationDriver` + `PlutoVGScanner`, and `PlutoPaintingDriver` (a `BrushPaintingDriver`) + `PlutoBrush`, both registered by `VenusianPlutoServiceProvider`.
2. **Tiers:** `PlutoVGScanner` implements the core `Scanner` (`path()`), `ShapeScanner` (ellipses, rings, round rects and round rings as PlutoVG geometry, `PlutoShapes`), `MaskScanner` (`mask()`, which VelvetGE's `DirectDraw` lands with the store's `paintMasks()`) and `DirectScanner`. It has no shadow: Velvet hands that back undrawn. PlutoVG always anti-aliases, so `edges()` answers `Edges::ANTIALIASED` whatever was asked and nothing is cut to whole pixels here. Nothing in `src` uses Lustrous or another module.
3. **How a path becomes coverage:** filled in opaque white onto a scratch surface the size of the path's extents inside the clip (tiles of at most 4096×4096, stitched); `plutovg_surface_get_alpha()` reads it back as packed a8 in one C call. `mask()` answers that a8; `path()` run-length encodes the same bytes, so both answer identical coverage. In place: `PlutoVGScanner` is also a `DirectScanner`; `drawsInto()` holds for B G R A rows only (top first, stride a multiple of 4, little-endian host), where `fill()` wraps the memory with `plutovg_surface_create_for_address()`, clips to the scanner's clip and fills each path. PlutoVG's premultiplied source-over on stored bytes is VelvetGE's blend: within `PlutoVGScanner::BLEND` = 3 per byte (20,000 shapes, 2026-11-15; 2 bytes in 9 million reach 3). `PlutoBrush` draws solid shapes in place on B G R A too (save, clip to the command's cut, fill, restore); gradients always go through `plutovg_surface_blend_ramp()` so they keep VelvetGE's ramp sampling. In the workbench also set `Tolerance::$by['plutovg'] = PlutoVGScanner::BLEND;` (topside 9807279 reads it in the DirectDraw matrix).
4. **Parity is by tolerance** (`PlutoVGScanner::TOLERANCE` = 11 on simple shapes). Where a path's contours overlap inside one pixel, FreeType's rasteriser sums their coverage (up to 220 off at that pixel); under 1% of pixels, area within 0.5%. `plutovg` must not join topside's 'rasterization drivers' dataset (it holds drivers to VelvetGE's exact bytes).
5. **Testing:** `tests/PlutoVGParityTest.php` runs inside topside's suite. Workbench: copy venusian/topside's `composer.json`, `phpunit.xml`, `tests/` and `vendor/` into a scratch directory, symlink its `src` and `config`, autoload `Jovian\Rendering\Pluto\` from this package's `src/` in a bootstrap file named in `phpunit.xml`, copy the test into `tests/Rasterization/`, register the driver at the end of topside's `tests/Pest.php` (`LibraryDrivers::$rasterization['plutovg'] = new PlutoVGRasterizationDriver();`, after a `require_once` of the bootstrap: Pest reads `Pest.php` first), never in topside's 'rasterization drivers' dataset (VelvetGE's exact-bytes set). It then runs in 'every rasterization driver', which the DirectDraw matrix uses. Run the whole suite (2026-11-13, topside 7dee0bf: 2749 passed, 3 skipped).
6. **Brush:** `PlutoBrush` takes anti-aliased shape and gradpath commands only (`takes()` sees the edge mode). Shapes go through PlutoVG's rasterizer's `Rasterizer::lower()`, are built as PlutoVG paths by `PlutoShapes`, filled white on a scratch surface sized to the path's extents ∩ clip ∩ rows, and blended by `plutovg_surface_blend_colour()` / `_ramp()`, which carry VelvetGE's blend and ramp sampling: only coverage differs. Tolerance `PlutoBrush::TOLERANCE` = 40, `tests/PlutoBrushTest.php` (copy into the workbench's `tests/Painting/`). Run the workbench against topside's committed HEAD (a local clone), not a symlink: the live tree may hold another session's unfinished edits. 2026-11-13, topside eeed8ad: 3764 passed, 7 skipped, with PHP and with ext-rasterize's stroker (`TOPSIDE_STROKER=ext`).
7. **Version** follows venusian/framework's 0.x line: 0.11.0.

**No other module.** Nothing in `src` imports Lustrous (`Jovian\Engines\Velvet\…`) or another module: what PlutoVG can't do comes back undrawn. Lustrous appears only in tests, as the measuring reference. Check: `grep -rn "Jovian\\\\Engines\\\\Velvet" src` is empty.
